02 / 06 DESIGN BACKGROUND

创作背景

这个技能的设计出发点，不是重复已有的通用 AI 开发工作流，而是针对 Python 性能优化任务本身的复杂性，补齐流程控制、长上下文管理和经验复用上的缺口。

PROBLEM FRAME

为什么需要单独设计这个 Skill

REFERENCE CONTEXT

在调研 `Superpowers`、`OpenSpec` 和 `LongTaskForAgent` 之后，可以看到业界已经提供了三类成熟思路：微任务化、文档即上下文、文件系统状态机。这些框架对通用研发任务非常有效，但在性能优化场景中，仍然存在覆盖不完整的问题。

已有能力
结构化提问、计划拆解、文档制品链、长任务状态恢复、自动化循环。
性能优化的额外要求
基线采集、热点定位、专题迭代、实验记录、一致性验证，以及优化经验的持续沉淀与跨团队复用。
Observation
通用框架提供了工作流骨架，但没有直接覆盖完整的性能优化链路。
INSIGHT 01

性能优化是复杂综合任务

性能优化不是单次代码修改，而是从基线、分析、专题实验到验证的连续流程。它通常涉及多轮判断和实验，既需要稳定的流程控制，也会持续消耗较长的 Agent 上下文。

INSIGHT 02

现有框架无法直接覆盖完整链路

`superpowers`、`OpenSpec`、`LongTaskForAgent` 分别擅长流程拆解、文档制品和长任务状态机，但它们没有直接内建性能基线、瓶颈索引、专题优化和性能报告这一整套专用链路，因此需要在这些能力之上进一步封装。

INSIGHT 03

性能经验需要跨业务组复用

很多优化经验并不只属于单个项目，例如 NumPy 向量化、I/O 路径优化、内存管理等模式，应该被抽取成可复用知识，在不同业务组和后续项目之间共享，而不是停留在某次聊天记录或某个成员的个人经验里。

03 / 06 WORKFLOW OVERVIEW

完整工作流

从性能基线到瓶颈定位，再到专题化优化迭代，形成可执行、可记录、可验证的三步流程。

STEP 01

建立性能基线

通过真实运行数据建立当前系统的性能参考面，明确耗时分布、调用链结构和关键指标，避免在缺乏证据的情况下直接修改代码。

目标
获取可信的初始数据，为后续优化提供比较基准。
方法
使用 `viztracer` 等工具采样，记录函数耗时、调用频次和热点路径。
产出
基线报告、追踪数据文件、关键指标摘要。
STEP 02

性能瓶颈分析

将 Profiling 结果与代码结构、数据路径、算法复杂度结合起来，识别真正限制吞吐和延迟的热点模块，而不是只看表面耗时。

目标
从整体数据中定位值得投入优化的核心瓶颈。
方法
结合调用链、热点函数与代码上下文，拆分为算法、I/O、并发、内存等分析方向。
产出
瓶颈清单、优先级判断、专题优化候选项。
STEP 03

专题迭代优化

围绕具体专题逐轮迭代，例如 NumPy 向量化、I/O 路径优化或内存占用控制；每轮都回到基线比较，确认收益与副作用。

目标
在可控范围内逐步提高性能，并持续验证优化结果。
方法
按专题拆解需求、实施修改、回归测试，并与前一轮结果进行对比。
产出
优化方案、实验记录、对比报告与下一轮候选方向。

STATE 01

阶段状态可恢复

每一阶段都形成独立的 Markdown 记录，包含当前目标、关键发现、未完成事项和下一步建议。任务中断后可以直接从文档恢复状态，而不依赖上下文窗口残留信息。

STATE 02

阶段之间有清晰边界

基线、分析、专题优化分别沉淀为不同层级的文档和数据产物。这样既能保留完整主线，也能防止不同轮次的实验结论相互覆盖或混淆。

STATE 03

支持协作与交接

结构化文档不仅服务于当前 Agent，也便于后续开发者或新的 Agent 接手任务。交接时只需读取已有产物，就能理解当前进度、历史决策和剩余问题。

EVOLVE 01

优化前先查阅知识库

Agent 在执行性能优化时，会先查阅 `knowledge/` 中已有的策略与分类经验，把通用方法论和常见优化模式作为决策参考，而不是每次从零开始推断。

EVOLVE 02

独立技能负责经验回写

完成优化后，可通过独立的 `python-vibeperf-evolution` 技能收集场景、原始写法、优化写法和提升效果，再将这条经验格式化并写入对应的知识分类文件。

EVOLVE 03

分类与索引同步扩展

如果经验属于新的特定库或领域，会动态创建新的 Markdown 分类文件，并同步更新 `INDEX.md` 中的索引入口，保证知识库可以持续扩展而不破坏原有结构。

06 / 06 SYSTEM CLOSURE

总结

`python-vibeperf` 将优化执行、状态沉淀与知识演进串联为统一闭环，使每一轮性能优化都能成为下一轮工作的输入。

CLOSURE

从单次优化到持续进化

这个技能体系不是一次性的性能排查脚本，而是一套可以长期运行的工程化方法：先执行三步优化流程，再把产物沉淀为可恢复状态，并在任务结束后把新增经验写回知识库。

输入
项目代码、运行数据、轮次产物、既有知识库。
输出
优化方案、过程文档、对比结果、可复用经验。
结果
每一轮优化都会留下可验证的证据、可恢复的状态和可复用的知识，使后续任务不必从零开始。
