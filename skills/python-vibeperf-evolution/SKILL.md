# Python 性能优化自我进化 (Self-Evolution)

## 概述

本技能是一个独立的配套工具，专门负责收集、验证、抽象和沉淀 Python 性能优化经验。它的目标不是把项目复盘直接追加到知识库，而是从真实优化结果中提炼可迁移模式，并将业务上下文降级为案例证据。

不同项目、不同 LLM 调用本技能时，必须遵循同一套通用性验证流程，避免把单一项目有效的做法误写成普遍最佳实践。

## 触发条件

当用户提出以下类型的需求时，应触发本技能：

- `/python-vibeperf-evolution`
- "记录一条性能优化经验"
- "把刚才的优化方法沉淀到知识库里"

## 核心工作流

当本技能被触发时，请按照以下步骤执行：

1. **读取治理规则**
   - 必须先读取 `skills/python-vibeperf/knowledge/INDEX.md`。
   - 必须读取 `skills/python-vibeperf/knowledge/_TEMPLATE.md`。
   - 必须读取 `skills/python-vibeperf/knowledge/cases/README.md` 的摘要索引，判断是否已有相似案例。
   - 根据候选分类读取目标文件，例如 `principles/`、`libraries/` 或 `domains/` 下的相关文档。

2. **收集信息**
   - 引导用户提供本次性能优化的详细经验。
   - 必须包含以下关键信息：
     - **场景**: 遇到性能问题的具体上下文。
     - **原始写法**: 存在性能问题的代码片段。
     - **优化写法**: 改进后的代码片段。
     - **提升效果**: 具体的性能提升数据（如耗时从 10s 降至 1s）。
     - **验证方式**: profile、benchmark、测试用例或输出一致性验证。
     - **运行边界**: Python 版本、依赖版本、数据规模、硬件/OS、并发模式等。

3. **通用性验证**
   - 在写入通用条目前，必须显式回答以下问题：
     - 这个经验脱离当前项目后是否仍成立？
     - 它依赖哪些库、版本、数据规模、硬件、操作系统或运行模式？
     - 哪些内容只是业务上下文，必须移入 `cases/`？
     - 什么情况下这个优化可能失效、变慢或改变语义？
     - 是否改变精度、排序、异常行为、资源生命周期或并发安全性？
     - 是否有足够证据证明性能提升和输出一致性？
   - 如果无法回答这些问题，不得写入 `principles/`、`libraries/` 或 `domains/`。

4. **归类判断**
   - 写入 `principles/`: 经验不依赖特定第三方库，可以通过多种实现方式落地，核心价值是决策原则。
   - 写入 `libraries/`: 经验依赖特定库 API、版本行为、输入格式或内部实现。
   - 写入 `domains/`: 经验横跨多个库或工具，核心问题是领域数据流、建模方式或组合策略。
   - 写入 `cases/`: 经验有参考价值但尚未抽象成通用模式，或包含较多项目上下文、环境数据、业务边界。
   - 拒绝写入: 缺少真实性能证据、缺少语义一致性验证、无法说明适用条件，或没有迁移价值。

5. **强制降级判断**
   - 出现以下情况时，默认不能直接写入通用知识条目，只能写入 `cases/` 或拒绝写入：
     - 核心描述依赖项目私有对象、函数名、目录结构或业务流程。
     - 性能结论只来自单一环境的绝对耗时，且没有统计方法。
     - 只有“提升 xx 倍”，没有适用条件、反例和语义一致性验证。
     - 经验依赖特定领域数据分布，但没有说明数据分布边界。
     - 代码示例无法脱离项目运行，或包含过多业务字段。

6. **执行写入**
   - **检查软链接**：在写入之前，必须检查 `skills/python-vibeperf/knowledge/` 目录或其上级目录是否是通过软链接（Symlink）创建的。如果是，则必须解析（Resolve）出原始的真实路径，并将文件写入到原始位置。
   - 写入通用条目时，必须使用 `_TEMPLATE.md` 的字段结构，并写清适用条件、不适用风险和验证方式。
   - 写入案例时，必须使用 `cases/README.md` 中的摘要格式更新索引；完整案例只保留最小必要上下文。
   - 如果对应分类文件不存在，只有在主题边界清晰且会持续增长时才创建新文件。

7. **更新索引**
   - 如果创建、移动或删除任何知识文件，必须同步更新 `skills/python-vibeperf/knowledge/INDEX.md`（同样需解析软链接到真实路径）。
   - 如果写入 `cases/`，必须同步更新 `skills/python-vibeperf/knowledge/cases/README.md`。
   - 如果只更新 `cases/`，不能修改主流程文档使其默认读取案例正文。

## 约束

- 所有通用知识条目必须格式清晰，包含通用场景、适用条件、不适用风险、原始模式、推荐模式和验证方式。
- 写入知识库前，必须确保经验的普适性和正确性；不能依赖 LLM 自行判断或省略检查。
- 必须严格遵循 `skills/python-vibeperf/knowledge/` 目录的结构和索引规则。
- 真实案例只能作为证据，不作为规则；性能数字必须带环境、数据规模和统计方法。
- 主流程默认只读取 `cases/README.md` 摘要索引，不读取所有案例正文，避免小上下文模型被案例噪声污染。
- **软链接处理**：必须始终检查并解析软链接，确保所有的修改和创建都发生在真实的原始目录下，避免破坏软链接结构。
