# 知识条目模板

本模板用于 `principles/`、`libraries/` 和 `domains/` 下的可复用知识条目。真实项目上下文和完整性能数据应写入 `cases/`，通用条目只保留可迁移的模式、边界和证据链接。

## <优化模式名称>

- **通用场景**: 描述问题形态，不写项目私有对象、目录、函数名或业务流程。
- **适用条件**: 说明数据规模、调用频率、依赖版本、运行环境、并发/内存前提。
- **不适用/风险**: 说明可能变慢、改变语义、引入内存泄漏、破坏并发安全或兼容性的情况。
- **原始模式**: 用最小代码片段展示反模式，避免复制完整业务代码。
- **推荐模式**: 用最小代码片段展示可复用优化方式，必要时标注版本要求。
- **验证方式**: 说明如何用 profile、benchmark 或测试证明性能收益和语义一致性。
- **案例证据（可选）**: 链接到 `cases/` 中的真实案例摘要。性能数字只能作为案例证据，不作为普遍承诺。

## 写入前检查

- 该经验是否脱离当前项目仍成立？
- 该经验依赖哪些库、版本、数据规模、硬件、操作系统或运行模式？
- 哪些内容只是业务上下文，应移动到 `cases/`？
- 什么情况下该优化可能失效、变慢或改变语义？
- 是否有足够证据证明性能提升和输出一致性？

## 强制降级到 `cases/` 的情况

- 核心描述依赖项目私有对象、函数名、目录结构或业务流程。
- 性能结论只来自单一环境的绝对耗时，且没有统计方法。
- 只有“提升 xx 倍”，没有适用条件、反例和语义一致性验证。
- 经验依赖特定领域数据分布，但没有说明数据分布边界。
- 代码示例无法脱离项目运行，或包含过多业务字段。
