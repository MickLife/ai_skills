# JSON 序列化

本文件记录 JSON 编码、写入和兼容性相关的跨库性能模式。具体项目数据格式只能作为案例证据。

## 编码器选择：标准兼容性与吞吐权衡

- **通用场景**: 大量 JSON 序列化或落盘成为热点。
- **适用条件**: 输出对象可以被目标编码器正确处理，且兼容性差异可接受。
- **不适用/风险**: 不同编码器对 `datetime`、`Decimal`、NumPy 类型、NaN/Infinity、键类型和缩进格式支持不同。
- **原始模式**:
  ```python
  import json

  with open("data.json", "w", encoding="utf-8") as f:
      json.dump(records, f)
  ```
- **推荐模式**:
  ```python
  import orjson

  with open("data.json", "wb") as f:
      f.write(orjson.dumps(records))
  ```
- **验证方式**: 在目标对象结构和目标环境中比较吞吐、输出大小、兼容性和解析结果；不要把单一环境的绝对耗时写成普遍结论。

## `bytes` / `str` 写入路径差异

- **通用场景**: 从 `json.dump()` 切换到返回 `bytes` 的编码器。
- **适用条件**: 文件或网络写入路径可以接受二进制数据。
- **不适用/风险**: 如果调用方要求 `str`，额外 decode 可能抵消部分收益；文本文件模式不能直接写 `bytes`。
- **推荐模式**: 对返回 `bytes` 的编码器使用二进制写入，避免无必要的编解码。
- **验证方式**: 确认输出编码、换行、压缩和下游读取行为一致。

## NaN、Infinity 与特殊类型处理

- **通用场景**: JSON 数据包含缺失值、无穷值、时间、Decimal、自定义对象或数组类型。
- **适用条件**: 已明确下游消费者对非标准 JSON 值和特殊类型的期望。
- **不适用/风险**: 有些编码器会把非有限浮点值转为 `null`，有些会输出非标准 JSON；这可能改变语义。
- **推荐模式**: 在序列化前做数据清洗或显式转换，并用 schema 或 golden 文件测试输出。
- **验证方式**: 覆盖 NaN、Infinity、None、日期、Decimal、数组和嵌套对象。

## 基准测试方法

- **通用场景**: 需要选择 JSON 编码器或证明写入优化有效。
- **适用条件**: 有代表性数据样本和明确目标环境。
- **不适用/风险**: 只测 toy data、只测序列化不测落盘、混合冷启动和热启动都会误导结论。
- **推荐模式**: 分别测量编码、写入、压缩和下游读取；记录 OS、Python 版本、库版本、数据规模和统计方法。
- **验证方式**: 多次运行取中位数或分位数，保存脚本和输入摘要；完整数据表放入 `cases/` 或项目产物，不复制进通用条目。
