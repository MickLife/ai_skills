# 空间计算

本文件记录跨 SciPy、Shapely、PyProj、NumPy 等库的空间计算性能模式。具体 API 细节应链接到 `libraries/`，不要在此重复维护。

## 空间索引优先于暴力几何匹配

- **通用场景**: 点、线、面之间存在大量邻域查询、相交判断或最近邻匹配。
- **适用条件**: 数据规模较大，暴力两两比较成为热点，且空间关系可以用索引裁剪候选集合。
- **不适用/风险**: 数据很小、查询次数很少或索引构建成本过高时，直接计算可能更简单。
- **推荐模式**: 使用 `cKDTree`、STRtree 或领域库索引先缩小候选集，再执行精确判断。
- **相关知识**: [`../libraries/scipy.md`](../libraries/scipy.md)、[`../libraries/shapely.md`](../libraries/shapely.md)。

## 对不变几何或点集复用预处理结构

- **通用场景**: 同一批坐标、同一个复杂几何或同一空间索引被多次查询。
- **适用条件**: 输入数据在复用期间不变，缓存键能覆盖数据版本、坐标系和过滤参数。
- **不适用/风险**: 几何或坐标集变化后未失效会产生错误结果；无界缓存会消耗大量内存。
- **推荐模式**: 将索引、prepare 后的几何、坐标转换器或中间数组作为显式预处理产物，并设计失效条件。
- **相关知识**: [`../principles/core-strategies.md`](../principles/core-strategies.md)、[`../libraries/pyproj.md`](../libraries/pyproj.md)。

## 批量转换、批量构造与批量查询

- **通用场景**: 空间流水线中逐点转换坐标、逐个构造几何或逐点查询邻域。
- **适用条件**: 输入可以整理为数组或批量结构，且输出顺序和异常处理可控。
- **不适用/风险**: 批量处理可能提高内存峰值；需要分块控制资源。
- **推荐模式**: 优先使用 PyProj 批量转换、Shapely 2.x 批量构造、SciPy 批量查询和 NumPy 批量后处理。
- **相关知识**: [`../libraries/pyproj.md`](../libraries/pyproj.md)、[`../libraries/shapely.md`](../libraries/shapely.md)、[`../libraries/scipy.md`](../libraries/scipy.md)、[`../libraries/numpy.md`](../libraries/numpy.md)。

## 坐标系转换与空间谓词的组合优化

- **通用场景**: 空间谓词判断前后伴随坐标转换、过滤、几何构造和索引查询。
- **适用条件**: profile 显示成本分散在多个空间处理环节，而不是单一 API 调用。
- **不适用/风险**: 只优化某个库调用可能转移瓶颈；坐标系或几何语义错误会让性能优化无意义。
- **推荐模式**: 先建立端到端空间数据流，再逐段测量转换、构造、索引、谓词和后处理成本。
- **验证方式**: 同时验证坐标精度、空间关系语义和性能指标。
