# 数据结构与基础语法

本文件记录 Python 内置数据结构和基础语法层面的通用性能模式。微优化只有在 profile 证明属于极热路径时才应采用。

## 成员检查：用 Set/Dict 替代线性扫描

- **通用场景**: 在循环中频繁执行 `item in collection`，且 `collection` 是列表或元组。
- **适用条件**: 集合较大、查询次数多，并且元素可哈希。
- **不适用/风险**: 数据量很小、需要保留重复元素或顺序语义时，转换为 `set` 可能没有收益或改变语义。
- **原始模式**:
  ```python
  allowed = [1, 2, 3, 4]
  if item in allowed:
      handle(item)
  ```
- **推荐模式**:
  ```python
  allowed = {1, 2, 3, 4}
  if item in allowed:
      handle(item)
  ```
- **验证方式**: 比较构建集合的成本和多次查询节省的时间；补充重复元素、顺序依赖相关测试。

## 字符串拼接：用 join 或缓冲收集

- **通用场景**: 循环中不断用 `+` 或 `+=` 拼接字符串。
- **适用条件**: 拼接片段数量较多，或字符串总长度较大。
- **不适用/风险**: 片段数量很少时无需改写；如果需要流式输出，应考虑直接写入缓冲区或文件对象。
- **原始模式**:
  ```python
  result = ""
  for part in parts:
      result += part
  ```
- **推荐模式**:
  ```python
  result = "".join(parts)
  ```
- **验证方式**: 用真实片段数量和长度做 benchmark，确认内存峰值可接受。

## 微优化：仅在极热路径中考虑局部绑定

- **通用场景**: profile 证明极小函数或紧凑循环中存在大量属性查找、全局查找或动态分派。
- **适用条件**: 循环次数巨大，且更高层级的算法、数据结构和批处理优化已经完成。
- **不适用/风险**: 现代 Python 版本已优化部分查找路径；过早局部绑定会降低可读性，收益也可能消失。
- **原始模式**:
  ```python
  import math

  def compute(values):
      return [math.sqrt(x) for x in values]
  ```
- **推荐模式**:
  ```python
  import math

  def compute(values):
      sqrt = math.sqrt
      return [sqrt(x) for x in values]
  ```
- **验证方式**: 只在目标 Python 版本和真实输入规模下 micro-bench；若收益不稳定，应保留可读写法。

## 排序、分组与索引结构的选择

- **通用场景**: 代码反复排序、分组、扫描或按键查找同一批数据。
- **适用条件**: 数据集在多次查询之间保持不变，或预处理成本能被多次查询摊薄。
- **不适用/风险**: 输入频繁变化时，维护索引可能比直接扫描更慢。
- **推荐模式**: 根据访问模式选择 `dict`、`set`、排序数组、堆、前缀表或专用索引结构。
- **验证方式**: 同时衡量构建成本、查询成本和更新成本。
