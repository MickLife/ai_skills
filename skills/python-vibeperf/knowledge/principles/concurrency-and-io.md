# 并发与 I/O

本文件记录跨库的并发、I/O 和序列化吞吐优化原则。具体 JSON 编码器细节见 [`../domains/json-serialization.md`](../domains/json-serialization.md)。

## CPU 密集型任务：进程、原生扩展或向量化

- **通用场景**: 热点主要是 Python 层计算，线程无法有效利用多核。
- **适用条件**: 单个任务计算量足够大，能够抵消进程创建、调度和序列化成本。
- **不适用/风险**: 小任务、高频跨进程传输大对象或共享状态复杂时，多进程可能更慢。
- **推荐模式**: 优先评估算法、向量化和原生扩展；需要多核时使用 `multiprocessing` 或 `ProcessPoolExecutor`。
- **验证方式**: 分别测量单任务耗时、序列化成本、进程池启动成本和端到端吞吐。

## I/O 密集型任务：异步或线程池

- **通用场景**: 大量时间花在网络请求、数据库查询、磁盘读写或外部服务等待。
- **适用条件**: I/O 操作可以并发等待，且目标库支持异步或能安全在线程中调用。
- **不适用/风险**: 下游服务限流、连接池过小、事务顺序依赖或库线程不安全时，并发会放大问题。
- **推荐模式**: 对原生异步库使用 `asyncio`；对阻塞库使用 `ThreadPoolExecutor`，并显式控制并发度。
- **验证方式**: 观察吞吐、尾延迟、错误率、连接池耗尽和下游负载。

## 批量 I/O：减少系统调用和网络往返

- **通用场景**: 循环中逐条写文件、逐条插入数据库或逐条调用远程 API。
- **适用条件**: 业务允许批量提交，且失败重试、事务边界和内存上限可控。
- **不适用/风险**: 批量过大会增加延迟、内存峰值和失败回滚成本。
- **推荐模式**: 使用批量插入、缓冲写入、分块上传或合并请求；按内存和延迟目标选择批大小。
- **验证方式**: 对比不同批大小下的吞吐、尾延迟、失败恢复成本和内存峰值。

## 并发优化的成本边界

- **通用场景**: 准备通过并发提升性能，但瓶颈来源尚不清楚。
- **适用条件**: profile 能证明等待或可并行计算占主要耗时。
- **不适用/风险**: 并发可能引入竞态、死锁、顺序变化、资源耗尽和调试成本。
- **推荐模式**: 先用性能数据确认瓶颈类型，再选择线程、进程、异步、批处理或向量化。
- **验证方式**: 增加压力测试和输出一致性测试，监控 CPU、内存、I/O、锁等待和错误率。
