# 内存管理

本文件记录 Python 内存占用、对象生命周期和数据拷贝相关的通用优化经验。

## 使用生成器处理大数据集

- **通用场景**: 读取大文件、批量处理记录或逐条消费数据流。
- **适用条件**: 下游逻辑可以逐条或分批处理，不需要一次性随机访问全部数据。
- **不适用/风险**: 如果后续需要多次遍历或随机访问，生成器可能导致重复 I/O 或复杂状态管理。
- **原始模式**:
  ```python
  def read_records(path):
      with open(path) as f:
          return f.readlines()
  ```
- **推荐模式**:
  ```python
  def iter_records(path):
      with open(path) as f:
          for line in f:
              yield line
  ```
- **验证方式**: 同时记录峰值内存、首条数据可用时间和端到端耗时。

## 避免不必要的对象拷贝

- **通用场景**: 热路径中传递大型列表、字典、数组或 DataFrame 时产生复制。
- **适用条件**: 调用方和被调用方可以共享只读数据，或可以用视图表达子集。
- **不适用/风险**: 可变对象共享可能引入意外修改；视图可能延长底层大对象生命周期。
- **推荐模式**: 优先传递引用或视图；只有需要隔离修改或缩短生命周期时才显式复制。
- **验证方式**: 检查对象别名、可变性测试和峰值内存。

## 使用 `__slots__` 优化大量轻量对象

- **通用场景**: 需要创建大量结构固定的小对象。
- **适用条件**: 属性集合稳定，不依赖动态添加属性、实例 `__dict__` 或弱引用等特性。
- **不适用/风险**: `__slots__` 会影响序列化、调试、继承和动态属性扩展。
- **原始模式**:
  ```python
  class Point:
      def __init__(self, x, y):
          self.x = x
          self.y = y
  ```
- **推荐模式**:
  ```python
  class Point:
      __slots__ = ("x", "y")

      def __init__(self, x, y):
          self.x = x
          self.y = y
  ```
- **验证方式**: 用目标对象数量衡量内存峰值和创建耗时；确认序列化和动态属性需求。

## 控制缓存和预计算结果的生命周期

- **通用场景**: 使用缓存、索引或预计算结果降低 CPU 开销。
- **适用条件**: 缓存结果可复用，且能设定容量、失效或释放时机。
- **不适用/风险**: 无界缓存容易把 CPU 优化转化为内存泄漏。
- **推荐模式**: 对小结果使用 `lru_cache(maxsize=...)`；对大对象使用显式生命周期管理和监控。
- **验证方式**: 压测长时间运行场景，观察缓存命中率和内存曲线。
