# 性能分析

## 目标

本阶段的目标是建立 Python 代码的性能基线，收集真实的性能数据，为后续的性能分析和优化提供客观依据。

## 过程与规则

**状态管理：**
- 进入本阶段时，更新 `docs/perf/rounds/<timestamp>/PROGRESS.md`，将状态标记为“进行中”。
- 完成本阶段时，更新 `PROGRESS.md`，将状态标记为“已完成”，并简要记录收集到的基线数据概况。


1. **阅读并完全理解VizTracer 使用指南**
   - [viztracer-guide.md](viztracer-guide.md)

2. **确认性能测试需求**
   - **读取并执行 `brainstorming` 技能**：使用 Read 工具读取系统可用技能列表中的 `brainstorming` 技能文档，并严格遵循其指令，与用户探讨并确认项目背景、测试目标、脚本路径、核心输入参数等。
   - 确认输出 JSON 文件的保存位置和命名规则。
   - 确认是否需要调整默认参数配置。

3. **运行双重基线测试**
   - **纯净运行 (无 VizTracer)**：直接运行脚本，记录真实的执行时间核心指标，作为最终优化效果的对比基准。
   - **追踪运行 (使用 VizTracer)**：遵循`viztracer-guide.md`的指导和配置，使用 VizTracer 再次运行脚本，生成 JSON 格式的性能数据，用于后续的详细瓶颈分析。
   - 确保追踪数据完整且符合预期。

4. **保存追踪数据**
   - 将 JSON 文件保存到产物目录
   - 确保数据可追溯和复用

**约束条件：**

- 未建立基线前，不进入优化实现
- 未确认真实输入特征前，不编写实验数据
- 确保输出 JSON 文件的路径存在

## 输出产物

在 `docs/perf/rounds/<timestamp>/01-baseline/` 下生成：

- **BASELINE_REQUEST.md**：测试目标、参数与配置
- **BASELINE_RUN.md**：实际执行命令、输入特征与环境（包含纯净运行和追踪运行的记录）
- **traces/**：VizTracer 生成的 JSON 追踪数据文件
